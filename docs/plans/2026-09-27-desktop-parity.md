# Исправление desktop-паритета PostHog

Исправляем подтверждённые проблемы Windows в существующем Dart core, сохраняя общий Flutter API и границы между facade, desktop platform, core и файловым хранилищем. Основание: Windows-прогон 4198e7d и сверка Android 3.70.0/iOS 3.80.0 с SDK specs. Одно отличие от мобильного SDK само по себе не является основанием для изменения: при конфликте выбираем опубликованный контракт и проверяем действующие тесты.

Основной результат: некорректные группы не прекращают capture; legacy flags читаются; серверный Retry-After соблюдается; caller session ID сохраняется в событии; восстановленная очередь сразу подчиняется лимиту. Также устраняем подавление последнего person update, сохраняем документированный приоритет event/session/registered properties и восстанавливаем Windows timezone. Публичные методы и настройки не добавляются.

Очередь остаётся у текущего stateless core. Серверная пауза блокирует повторные flush и автоматические попытки до срока, отменяется при close и не меняет обычные retries без заголовка. Лимит восстановленных событий применяется до планирования отправки через существующий queue API; формат файлов и ownership не меняются.

Groups читаются безопасно во всех потребителях. Существующие корректные persisted maps продолжают работать; миграция в отдельное хранилище не нужна, поскольку старое состояние не позволяет отличить register от group. Legacy flags нормализуются в существующую модель: rich response, включая пустой flags, остаётся приоритетным; partial/quota metadata сохраняются. Session override влияет только на событие, не на внутреннюю сессию.

Windows timezone читается через системную ICU посредством dart:ffi, как существующий Windows version resource. При недоступности платформенной функции SDK продолжает работать без timezone. Новых зависимостей и собственной таблицы Windows/IANA нет.

Structured logs требуют самостоятельного OTLP transport/queue и находятся на отдельном решении пользователя. Replay, surveys, push и native crash hooks не включаются как побочный эффект исправления analytics. Не переносим Android-особенности, противоречащие spec: удаление exception steps при opt-out, raw malformed payload и обязательное исключение feature props из capture. Bootstrap persistence и read-only session getter согласуются с iOS и существующей архитектурой, поэтому не меняются только ради Android.

Каждое исправление получает воспроизводимый regression test через существующий публичный контракт. Закрываем Windows teardown и CRLF-падения, затем запускаем analyze, API snapshot check, весь пакетный test suite и Release-драйвер Windows с обновлёнными обоснованными ожиданиями. Старые результаты сохраняются отдельно. Нативные device-прогоны Android/iOS и интеграция новой версии в VPN-приложение остаются отдельными границами проверки; результаты Windows не выдаются за них.
